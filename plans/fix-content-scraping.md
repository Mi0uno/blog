# 内容抓取范围异常排查与修复指南

## 1. 问题分析：为何会出现“抓取范围异常”？

在开发博客或内容网站时，预期仅读取 `articles` 目录，却加载了项目其他文件的原因，通常归结为以下核心技术点：

### A. Glob 模式过于宽泛 (The "Glob" Problem)
这是最常见的原因。
*   **错误模式**: `**/*.md`
    *   `**` (Double Star) 表示**递归匹配任意深度的子目录**。
    *   这会匹配 `src/articles/a.md`，也会匹配 `node_modules/package/README.md`，甚至 `plans/architecture.md`。
*   **正确模式**: `articles/*.md` 或 `./articles/*.md`
    *   仅匹配 `articles` 目录下的直接子文件，不包含子目录。

### B. 静态生成器/构建工具配置错误
*   **Hugo/Hexo**: 配置文件 (`config.toml` / `_config.yml`) 中的 `contentDir` 或 `source_dir` 设置为了根目录 `.` 而不是 `content` 或 `source`。
*   **Vite/Webpack**: 使用了 `import.meta.glob` 或 `require.context` 时未指定具体目录。

### C. 递归函数未设限
*   在使用 Node.js `fs` 模块编写自定义脚本时，使用了递归遍历函数（如 `walkDir`）但没有过滤 `node_modules` 或 `.git` 目录。

## 2. 排查清单 (Checklist)

请对照以下清单检查您的代码或配置：

- [ ] **检查 Glob 模式**: 是否使用了 `**`？如果是，请确认是否真的需要递归。
- [ ] **检查根目录设置**: 数据获取函数的 `root` 或 `basePath` 是否指向了项目根目录而非 `articles` 目录？
- [ ] **检查排除项 (Excludes)**: 是否显式排除了 `node_modules`、`.git`、`dist` 等目录？
- [ ] **检查前端路由**: 动态路由（如 `[...slug]`）是否没有验证路径前缀，导致可以通过 URL 访问任意文件？

## 3. 修复代码示例 (针对主流框架)

### 场景 A: Vite / React (当前项目环境)

在 Vite 中，推荐使用 `import.meta.glob`。

**❌ 错误写法 (会导致扫描整个项目):**
```typescript
// 这会匹配项目内所有 md 文件，包括 node_modules
const allMarkdown = import.meta.glob('**/*.md');
```

**✅ 正确写法 (仅匹配特定目录):**
```typescript
// src/utils/getArticles.ts

// 1. 仅匹配当前目录下的 articles 文件夹内的 md 文件 (非递归)
const articles = import.meta.glob('/public/articles/*.md'); 
// 或者如果文件在 src 下：
// const articles = import.meta.glob('../data/articles/*.md');

export function getArticleList() {
  return Object.keys(articles).map((path) => {
    // 从路径中提取文件名或其他信息
    const fileName = path.split('/').pop();
    return {
      path,
      fileName,
      // 可以在这里结合 frontmatter 解析逻辑
    };
  });
}
```

### 场景 B: Next.js / Node.js (服务端渲染/静态生成)

使用 Node.js 原生 `fs` 模块时，避免使用递归遍历，或者严格限制目录。

**✅ 正确写法 (fs.readdirSync):**
```typescript
// lib/posts.ts
import fs from 'fs';
import path from 'path';

// 关键：使用 path.join 锁定绝对路径，避免相对路径歧义
const postsDirectory = path.join(process.cwd(), 'articles');

export function getSortedPostsData() {
  // 关键：fs.readdirSync 默认不递归，只读取一级目录
  const fileNames = fs.readdirSync(postsDirectory);
  
  const allPostsData = fileNames
    .filter(fileName => fileName.endsWith('.md')) // 过滤非 md 文件
    .map(fileName => {
      const id = fileName.replace(/\.md$/, '');
      const fullPath = path.join(postsDirectory, fileName);
      const fileContents = fs.readFileSync(fullPath, 'utf8');
      // ... 解析 frontmatter ...
      return { id, ... };
    });

  return allPostsData;
}
```

### 场景 D: 自定义脚本 (递归遍历修复)

如果您编写了脚本来生成 `articles.json`，请确保过滤逻辑严谨。

**✅ 修复后的遍历逻辑:**
```javascript
const fs = require('fs');
const path = require('path');

function scanArticles(dir) {
    const files = fs.readdirSync(dir);
    
    files.forEach(file => {
        const fullPath = path.join(dir, file);
        const stat = fs.statSync(fullPath);

        if (stat.isDirectory()) {
            // 关键：跳过 node_modules 和 .git
            if (file === 'node_modules' || file === '.git' || file === 'dist') return;
            // 如果不需要递归子目录，直接 return 即可
            // scanArticles(fullPath); // 递归调用
        } else {
            if (path.extname(file) === '.md') {
                console.log('Found article:', file);
            }
        }
    });
}
```
